Implemented customizable spec templates end to end.

### What changed

- Sundial now seeds `sundial/templates/spec.md` during initialization and update without overwriting user customizations.
- `sundial spec create` renders the template body while preserving CLI-owned workflow frontmatter. Supported tokens are `{{id}}`, `{{title}}`, `{{status}}`, `{{created}}`, `{{updated}}`, and `{{created_by}}`.
- The Specs sidebar now shows **Customize Spec Template** directly above **Open Kanban View**. It targets the selected workspace, creates a missing template through the CLI, and opens the Markdown file for editing.
- Fixed the missing-template migration path to run `sundial update --root <project>` for an already initialized store. Root-only updates now refresh shared store assets without reinstalling agent runtimes.
- Added the `Sundial: Customize Spec Template` Command Palette entry and updated CLI/VS Code documentation.
- Updated release metadata to CLI `0.7.1` and VS Code `0.7.3`.
- Applied DR-0012, DR-0004, DR-0006, DR-0008, DR-0016, DR-0025, and DR-0026.
